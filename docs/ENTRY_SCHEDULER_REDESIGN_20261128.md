## Architecture and implementation plan

### 1. Deadline and failure evidence
- entry_timing.py: immutable absolute deadline derived from selector evidence or receipt-target header. Monotonic measurements for duration; wall/chain timestamps for actual expiry; explicitly record clock offset/whole-second resolution. No time budget extension. Shared deadline-aware retry policy: bounded short retry for recoverable quote errors, respect provider throttling (no hot retry for 429/auth); do not schedule work at or beyond deadline. If no time remains, record missed deadline with exact stage and previous error, not generic overwrite. Terminal decision always distinct from actual token/liquidity rejection. Retry until expiry only if safety proofs can be completed; no lower bound on successful purchases.
- Add append-only per-attempt timing evidence (stage, start/end wall and monotonic elapsed, deadline, outcome, classified reason, selection/intent id, block, no raw signed bytes or credentials). Flush at attempt boundaries and terminal transitions rather than fsync every RPC; record scheduling delay, head observed, receipt verification, quote, origin, signer lock, preflight, signing, submission, receipt. Retain first failure. No synchronous logging to external services.
- Regression fixtures above: failure at target+1.550 must allow a retry before target+3; failure at +2.759 or window+2.814 must not be assigned a futile wake beyond deadline; report exhausted stage if residual work won't fit. Inject a transient first failure and a genuinely non-sellable token separately.

### 2. One head clock owned by execution
- Shared head observation while probes active, coalesced in-flight request; poll promptly close to target with bounded cadence (initial design 250 ms near target, adaptive slower when far; validate provider capacity), or newHeads feed with HTTP canonical verification at target; choose simplest proven method after latency test. No separate per-token polling storm. Maintain timestamp of last successful observation and distinguish stale/unknown; no fabricated progress.
- Cache receipt-header proof during survival against immutable receipt block/hash. At target confirm current canonical receipt matches, fetch exact target header; parallelize independent read-only proofs; if reorg mismatch invalidate, no stale grant. Retain seconds mode and activity filter support. At N-1 no entry; at N eligible, at N+late no entry; 30 and 500 both tested; actual target timestamp, never head's later timestamp.
- monitor_snapshot.py reads a timestamped executor head only for active survival countdown. If head < receipt or stale, show unknown/stale; never >N. Terminal target proof may show 0 remaining when known. Detector head still separate diagnostic, no detector modification. Monitor remains read-only with full addresses, no extra RPC. Regression stale 550 display, stale/fresh head and 30/500.

### 3. Single entry job; prepare before gate, reuse verified data
- Separate read-only preparation from signing authority. Candidate prep begins during observation if useful (read-only detector/selector evidence, prewarm FX/session/router identities); no pre-PASS signing or speculative buy. Prepare receipt/header proof, FX and venue metadata during survival, retain live route policy. At target obtain fresh pinned-block quote at/after target; same block two-way main route and sacrifice sell quote, origin read independent; do not reuse pre-target price/quote for final authorization. Parallelize independent RPC reads with bounded concurrency; keep mandatory reorg/eligibility/cap/bans checks.
- Define typed immutable PreparedEntry(selectionId, token, amountWei, quote, quoteBlock, verifiedAt, survivalAnchor, targetBlock, origin evidence), created only by successful final gate. It is short-lived and not durable authority. Pass to existing LiveExecutor.buy directly in same entry task; no scheduler round-trip and no duplicate two-way quote/origin within that attempt. Check identity, same exact amount, proof freshness, current eligibility/revocation, campaign open, canonical target, deadline, lock/nonce before signing. On restart, never trust an in-memory proof; reconstruct canonical evidence and obtain fresh quotes if still within original deadline. Any failure remains bounded by original deadline; if reattempt required, fresh proof rather than stale reused prices.
- Keep normal no-sacrifice entry and other selectors through the same route/signer interface; legacy behaviors unchanged unless independently tested. Single active task key per selection across gate->main handoff; no simultaneous BUY/LAMB_CHECK duplicate. A canonical gate check must be possible despite unrelated position read-only jobs. Actual urgent exit retains wallet priority; no new buy ahead of a latched urgent exit or unresolved intent. Explicit conflict reason when nonce is unavailable; no new nonce authority. Quote/prep may proceed in parallel even if signing unavailable.
- Test with actual gate, actual route adapter and execution handoff: count calls, exactly one fresh two-way quote and one sacrifice sell quote/origin per successful attempt; block N-1 rejects, N allows, N+deadline rejects; revocation/route change/cap/intake closure during handoff blocks signing; restart after queued promotion revalidates; no duplicate intent.

### 4. Nonblocking supervisor and signer
- live_executor.run: no inline network await in the dispatch loop; receipt reconciliation independent single-flight worker. Ensure async SQLite mutation boundaries are synchronous atomic transactions. Read-only gate timing cannot be blocked by approvals, finance, held venue or quote tasks. Fair, bounded concurrent workers, earliest deadline among entry jobs; urgent actual sales preserve priority. Do not queue a new financial transaction when a nonce is unresolved. When a sale needs a nonce, mark explicit priority conflict rather than silently starving checks. No arbitrary global locks across read-only RPCs. Ensure sign/broadcast remains mutually exclusive by journal contract.
- wallet_transactions.py: move independent RPC preflight reads into bounded concurrent waves, preserve all checks (chain id, code, exact eth_call, exact estimateGas, live fee, pending nonce, balance). Metadata prewarm does not substitute for fresh mutable nonce/balance, no early signing. Check deadline after lock and immediately before signing, journal and first send. Single-flight broadcast per intent, persist attempt before external side effect; reconciliation may observe receipt while send response pending, terminal receipt state must never be overwritten by late broadcast result. No cancellation of an uncertain send to reuse nonce; do not resend after expiry. Prior urgent exit behavior unchanged; no new wallet.
- Stress tests: deliberately slow receipt RPC while unrelated gate progresses; slow/429 quote/estimation with successful retry or exact failure classification; two simultaneous passes, actual nonce busy and urgent exit, no duplicate transaction; slow broadcast + faster canonical receipt must retain confirmed state; restart with signed/uncertain/expired intents; no sign beyond deadline.

### 5. Verification and release
- Baseline regressions fail first, then pass on candidate. Run full historical suite and detector/selector/monitor unchanged tests. Verify static source diff. Keep user configuration and data untouched; new isolated branch; no live arming.
- Replay above observed timestamps with controllable clock and realistic injected network waits. Use 30 ms median/38.5 ms p95/485 ms observed metadata outlier as *measured metadata*, quote and estimate latency deliberately varied independently (not measured by capture). Sweep target age 0–1 s (integer chain timestamps), receipt delays, candidate overlaps, sustained load, 429s, reorg, activity, old approvals, stale FX and restart. At least one hundred attempts per scenario; publish counts and p50/p95/p99/worst for scheduling, verification, preflight, first send, receipt if available, reasons and missed rates. Distinguish successful proof vs provider/token rejection vs true conflicts; goal zero avoidable scheduler misses in workload, not 100% market success. Verify deadlines without relaxing them. Budget target (engineering target not measured): normal dispatch under .1–.25 s, no duplicate checks, quote/preflight concurrent within residual absolute time. Fail safe outside envelope.
- Run bounded read-only actual network benchmark using identical route and simulation path on eligible observed candidates (no signer/broadcast); no expensive broad log scan. Real quote and estimate timing must be measured before calling it operationally fast. Record wall/chain timestamp resolution and block cadence. No live round trip until separately authorised; actual mined timing cannot be guaranteed by local code. An offline test count alone is not a release gate.
- Deployment only after successful tests, source/provenance and known open-position/nonce state; preserve original running revision and stash. Never hot-swap workers or start both selectors. No assumption of direct local access. No unrequested changes to exposure.

## Decision

The previous deadline fix correctly prevented late deliberate entries, but converted existing fixed retry periods and redundant stages into deterministic failures. The right fix is the shared entry lifecycle, not relaxing deadlines or changing the selection/survival strategy. This document captures the real evidence and design constraints; it is not a released implementation.
